## 三、关键结论与数据

### 1P1D + KV 池化（问题闭环）

| 实验 | 结果 |
| --- | --- |
| A 原始配置 | ~85 分钟后引擎雪崩 |
| B +ACL_OP_INIT_MODE=1 | **不再雪崩**，但池写 -800 |
| C +FABRIC_MEM 三件套 | real_client 创建失败，引擎起不来 |
| D 官方 11-11 新配方 | 稳定，但 -800 复现（remote_engine 为 P 节点自身） |

- **定性**：配置层面已穷尽，根因 = 驱动 25.2.1 × v0.30.0-a3 镜像 CANN 配对下 HixlCS P2P 通道创建缺陷，用户侧不可修，待驱动/镜像升级（池化做成 `ENABLE_KV_POOL` 一键开关，升级后即翻案）
- **服务本身**：稳定可用——64K 回归 20/20 零失败，TPOT ~19ms（优于 30ms 指标），本地前缀缓存命中 ~47%，多轮 TTFT 20s→12s
- 沉淀：`DEPLOYMENT_RECORD_1P1D.md`（四组实验矩阵 + 两条错误链 + 运维坑清单，报障材料现成）

### 3P2D（架构修正后成功）

- 最终形态：每台独立 DP 组（P 台台 DP4/TP4、D 台台 DP8/TP2，EP16 全在机内 HCCS），连接器布局 `prefill{4,4}/decode{8,2}`，与 4P1D 已验证结构同构，无跨机 all-to-all 的 TPOT 风险
- 28 引擎（P 12 + D 16），唯一入口 `001:9200`
- 两条硬约束入库（README FAQ）：CANN EP 整除约束、跨机 DP 组 5 分钟集结窗口

## 五、问题与解决（摘要）

| 问题 | 解决 |
| --- | --- |
| KV 池化运行 85 分钟雪崩 | `ACL_OP_INIT_MODE=1` 根除（实验 B 验证） |
| 池写必失败 -800 | 四组对照定性驱动配对缺陷；退池保服务 + 一键开关留翻案口 |
| 3P2D 引擎 init 报 561002 | CANN 要求专家数整除 EP 组大小：EP48(128%48≠0)→改每台 EP16 |
| 跨机 DP 组互相等待/超时 | 5 分钟集结窗口 + master 先起仍不够 → 回退每台独立组，问题类别消除 |
| 运维类（pkill 自匹配、cp 交互覆盖、GitHub 链路慢） | 方括号技巧 / `yes\|cp -rf` / codeload tarball 直下，均已固化进文档 |
